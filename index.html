Architecture

The project is one binary with two faces: an interactive scene editor and a GPU path tracer, both reading and writing the same runtime Scene. There is no editor scene graph, no exporter, and no translation layer between the two — the editor's undo stack and the renderer's device buffers are both derived from a single authored file.

The five diagrams below are the top-down map: the system, the synchronization system, dirtiness, the file system, and the inside of the renderer.

System map

One runtime Scene is the hub. Two derived views hang off it and they are orthogonal — neither consumes the other: an authoring index for the editor, a compiled cache for the renderer. Everything that crosses to the GPU crosses as a sealed, immutable snapshot.

The synchronization system — epochs and the three channels

Every edit is an EditOp, and each op declares which render domains it touched. Nine monotonic counters live in one struct on the editor side; the renderer keeps its own mirror and diffs the two. Only three channels reach the GPU; anything else is an architecture violation.

GPU state is split by lifetime, which is the whole explanation of why a scene change is cheap: device-lifetime state (OptixEngine, the texture pool) survives it; session-lifetime state (accel structures, framebuffers, environment) dies with the geometry. The worker that delivers frames owns no GPU state at all.

Dirtiness — revisions and their consumers

A scene-scale fact that two or more subsystems display is derived once, by the model, behind the narrowest revision that can invalidate it — never by each view, per frame. Setting PPT_VALIDATE_DERIVED=1 re-derives on every access, so a missed bump surfaces as a named error instead of a panel that silently stops updating.

The compiled cache is mutated in place rather than recompiled on every edit only because a check proves the mutated cache equals a fresh compile(). A mutator that cannot satisfy that check must recompile.

The file system — library, project, codecs

An asset is the directory holding its asset.json — no UUID, no registry, no index. A ref resolves against the project directory or it is absolute, which makes a project self-contained by construction. The app-level assets/ tree is a library you instantiate from, never a base you resolve against. Every document is a codec: one writer, one reader, a round-trip test.

Inside the renderer — four layers, four buffers

Dependencies point one way only, and the direction is the architecture: the Renderer layer chooses what to compute, each layer below chooses how to run it on this hardware. CUDA never drives renderer architecture. Four raygen entry points own four distinct buffers, and only the camera pass is bit-reproducible at a fixed seed — the caustic splat uses atomicAdd, so it has a measurement floor of about 5e-7 by construction.
