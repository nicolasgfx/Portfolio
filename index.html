The renderer

Four areas of the renderer behind the gallery. Each item is present in the code today and named with the paper it implements; the case study below is where the depth is.

Spectral light transport

  • Every path carries four sampled wavelengths. RGB exists only at two boundaries: a role-aware uplift of authored values on the way in (Jakob & Hanika 2019) and the film's CIE 1931 projection to XYZ and linear sRGB on the way out. Dispersion, measured-conductor Fresnel and thin-film interference are evaluated per wavelength.
  • Next-event estimation combined with BSDF sampling by the power heuristic; path guiding over a spatial binary tree with adaptive directional quadtrees (Müller, Gross & Novák 2017), off by default; manifold next-event estimation for light that reaches the environment through a dielectric (Hanika, Droske & Fascione 2015).
  • Spectral random-walk subsurface scattering with equiangular in-scatter sampling (Kulla & Fajardo 2012); priority-based nested dielectrics (Schmidt & Budge 2002).

Light sampling & materials

  • Many-light sampling through a light BVH with importance bounds and cone unions (Conty Estevez & Kulla 2018); environment maps with piecewise-constant importance sampling, MIS compensation (Karlík et al. 2019) and portal-masked sampling for interiors lit through windows (Bitterli, Novák & Jarosz 2015).
  • Owen-scrambled Sobol on a Morton-coded pixel index with per-dimension digit permutation, after PBRT-v4's ZSobol (Ahmed & Wonka 2020): error spreads as screen-space blue noise at low sample counts while every 1D and 2D projection stays a stratified (0,2)-sequence.
  • GGX with height-correlated Smith masking (Heitz 2014), anisotropic and bounded VNDF sampling (Heitz 2018; Eto & Tokuyoshi 2023), rough dielectric transmission (Walter et al. 2007) and multiple-scattering compensation for conductors from directional-albedo tables (Kulla & Conty 2017; Turquin 2019); layered closures with coat-over-base coupling and a position-free Monte Carlo layer walk (Guo et al. 2018).

GPU architecture & performance

  • One renderer, two kinds of stage: OptiX raygen programs own everything that traces, native CUDA kernels own everything else. Each stage module is created only when its stage is reachable, and path state lives in structure-of-arrays between stages.
  • Two-level acceleration: one GAS per unique mesh with compaction, built in batches under a VRAM budget; the IAS alone is rebuilt when only transforms change. Textures carry mip chains with anisotropic filtering in BC7/BC4 artifacts keyed by BLAKE3, under a VRAM budget that halves the largest texture first.
  • Display chain in CUDA: firefly rejection (median + MAD), the OptiX AI denoiser with albedo and normal guides between two phases, mip-chain bloom, ACES, sRGB; NVTX ranges per stage for Nsight.

Verification & engineering decisions

  • A closure-level white furnace runs the production sampler over every material stack: controls held to 0.99–1.01, every coated stack in a measured two-sided band that may only tighten, the lossless coated case checked per cosine. A closed-form fixture, an albedo-1 sphere inside a clear glass ball in a radiance-1 environment, must integrate to 1.0 ± 0.01; it read 2.17 before the repair that found two full-weight estimators of one transport.
  • Chi-squared sampler-versus-pdf tests, Kolmogorov–Smirnov on the sampler, reciprocity tests, and architecture regression tests that pin invariants in source: no RGB in transport, one camera path body, one render dispatch point.
  • Every renderer change declares its acceptance tier before it is gated: byte-identical, estimator-identical, or a deliberate image change with a predicted direction. 75 numbered decision records carry Problem, Decision, Alternatives rejected, Enforcement and a falsifiable revisit trigger, and reversals stay on record: path guiding was rejected, then accepted on new evidence; an image-space caustic layer was rejected on visual judgement.

Case study: retiring the megakernel

One OptiX module held the whole camera path, so any BSDF edit recompiled all of it. Measured on 2026-09-11: a 35.9 MB module, 23.5 minutes of nvcc and a further 35.1 minutes of cold module creation on a disk-cache miss. Over an hour from a closure edit to a pixel was shaping the physics work: edits were batched and validated in bulk.

The split was my decision, taken in two recorded steps. A wavefront backend was not accepted on architecture alone but gated on a measurement, and once it passed it became the only renderer: OptiX stages own tracing, native CUDA kernels own shading, and a feature the new backend cannot serve is refused by name rather than approximated. The megakernel reference arm was retired a week later, once it was no longer built from the source under review. The implementation was AI-assisted; the gates were set before the work began.

Build and startup rows: the project's swap record, 2026-09-11, through the shipping binary. Rendering rows: Kroken and Watercolor at 1920×1080, 128–512 spp, authored settings, denoising off, both backends through the same binary, single interleaved runs. The subsurface stage is the named exception to the module figures: its 8.5 MB module takes 138 s to create cold and is built only for scenes with a subsurface material.

The parity gate was shown to fail before it was trusted: a mutant build with the pre-merge shadow policy restored landed near the pre-merge baseline instead of the merged source, and the glass-enclosure closed form read 2.31 for the mutant against 0.9986 for the migrated build. The sixth ladder rung is a heavy-tailed scene at 128 spp whose p99, block maximum and RMSE all fall as samples rise, the shape of noise rather than bias. The host round trip was measured too: 24–28 % of the render timeline at 640×360, about 16 µs per GPU operation, which is why the schedule now makes one device-to-host read per bounce, and a second only when the subsurface walk ran.

Architecture

The project is one binary with two faces: an interactive scene editor and a GPU path tracer, both reading and writing the same runtime Scene. There is no editor scene graph, no exporter, and no translation layer between the two — the editor's undo stack and the renderer's device buffers are both derived from a single authored file.

System map

One runtime Scene is the hub. Two derived views hang off it and they are orthogonal — neither consumes the other: an authoring index for the editor, a compiled cache for the renderer. Everything that crosses to the GPU crosses as a sealed, immutable snapshot.

The synchronization system — epochs and the three channels

Every edit is an EditOp, and each op declares which render domains it touched. Nine monotonic counters live in one struct on the editor side; the renderer keeps its own mirror and diffs the two. Only three channels reach the GPU; anything else is an architecture violation.

GPU state is split by lifetime, which is the whole explanation of why a scene change is cheap: device-lifetime state (the OptiX context and the texture pool) survives it; session-lifetime state (accel structures, framebuffers, environment) dies with the geometry. The worker that delivers frames owns no GPU state at all.

Dirtiness — revisions and their consumers

A scene-scale fact that two or more panels display is derived once, by the model, behind every revision counter that can invalidate it — never by each view, per frame. Setting PPT_VALIDATE_VIEWS=1 re-derives on every access, reports a mismatch and self-heals, so a missed bump surfaces as a logged error instead of a panel that silently stops updating.

The commit used to be a 610-line tree of incremental fast paths, each proved equal to a full re-derive by a parity test. Two measurements retired it: a full compile of a villa-sized scene emits rows at 0.0027 ms each, about 5.6 ms in total, while undoing a 200-row delete through the incremental path took 1121 ms against 38 ms for restoring an image and re-deriving. What is left is what a commit is: regrow what the definition says, then re-derive.

The file system — library, project, codecs

An asset is the directory holding its asset.json — no UUID, no registry, no index. A ref resolves against the project directory or it is absolute, which makes a project self-contained by construction. The app-level assets/ tree is a library you instantiate from, never a base you resolve against. Every document is a codec: one writer, one reader, a round-trip test.

Inside the renderer — the wavefront

Dependencies point one way only: the Renderer layer chooses what to compute, each layer below chooses how to run it on this hardware, and CUDA never drives renderer architecture. Inside that, two kinds of stage, and no stage is both: OptiX raygen programs own everything that traces, native CUDA kernels own everything else. Per bounce the traced rays are split into hit and miss queues; a preparation kernel builds the closure once and routes each hit by execution shape — never by material identity — to the cheapest kernel that can shade it. A light connection is resolved only after the shadow trace and, for the environment, the manifold solve, and it is folded into the path's estimate exactly once. The host reads the counters once per bounce, and a second time only when the subsurface walk ran.
